## Deployment contract

Build with Node24.5.0, pnpm10.17.1 and the checked-in Dockerfile for linux/arm64; preserve the mounted/data volume. Native mode requires an assigned workroom, native Core API access, a trusted native CA bundle, and server-side ForwardAuth verification. When mesh policy denies direct ForwardAuth from an extension, REPLAY_KAMIWAZA_VALIDATION_API selects the authorized public validation endpoint while REPLAY_KAMIWAZA_API retains the protected internal target. A hostname-scoped ingress configuration lets Replay receive its opaque session cookie without bypassing its own native authorization. Global platform auth remains enabled.

REPLAY_PLATFORM_SSO=true requires REPLAY_PUBLIC_ORIGIN to be HTTPS and included in REPLAY_ALLOWED_ORIGINS. The platform access_token cookie is verified by Core, sessions rotate on entry and bind to cookie continuity, and logout suppresses automatic reentry until Continue is selected. Arbitrary caller identity headers are not trusted.

For the qualified API route, set REPLAY_MODEL_BILLING=external and REPLAY_MODEL_TRANSPORT=responses and provide the existing authorized OPENAI_API_KEY through a server-only Secret. The model is the existing Luna default. No provider credential belongs in browser code, source archives or logs. Local Chat Completions remains an explicit optional configuration with its own100-request ledger, zero provider API billing and no public API fallback; it was not selected for the completed demo.
